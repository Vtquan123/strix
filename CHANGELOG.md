# Changelog

## 1.1.0

Strix's guarantees used to be prose the model was asked to follow. This release
turns the load-bearing ones into mechanism: the CLI refuses a move that skips a
gate, a hook stops the executor editing the board, and the docs are generated
from config rather than kept in step by hand.

### Upgrading an existing project

Refresh the seeded board template, which now carries the sections the gates
need:

```sh
cp "<plugin>/templates/strix/tasks/TEMPLATE.md" .strix/tasks/TEMPLATE.md
```

`/strix:init --force` does this too, but it also re-seeds the executor's config
files. Neither touches `.strix/knowledge/**`, the workstream registry, or the
executor's skill catalog. The SessionStart hook warns when the template is out
of date.

Tasks already on the board keep working. A task created before this release has
no `Base`, `Execution Report`, `Review Checklist` or `History` section, so
`strix-task move` refuses to advance it until those exist. Either paste the
missing sections in from the new template, or move it with
`--override "pre-1.1 task"`. An override is recorded in the task's History, and
`strix-task doctor` then treats that task's gates as deliberately waived rather
than reporting them forever — every other task is still checked.

`.strix/bin/strix-task` is regenerated by `/strix:init`; the new shim holds no
machine-specific path and is safe to commit. `.strix/local.yaml` (gitignored)
records where the plugin lives on this machine.

### The board enforces the lifecycle

- `strix-task move` allows only the transitions in `config/task-schema.yaml`,
  each behind a gate: **ready** (no template placeholders, Definition of Ready
  ticked, dependencies Done), **reported** (Execution Report filled), and
  **checklist** (Review Checklist filled). Anything else needs
  `--override "<reason>"`.
- Every move appends to the task's `## History` with the time, actor (`--by`),
  and reason. Moving to active records `Base`, the commit the work starts from.
- New commands: `note` (writes the Execution Report or Review Checklist),
  `check`, `next`, `diff` (the task's `Strix-Task: <ID>` commits since Base),
  and `new --lite` for TRIVIAL tasks.
- `doctor` also checks duplicate and mismatched IDs, EPICs on the board,
  unknown or cyclic dependencies, leftover placeholders, a missing Base, empty
  reports, and the registry status enum.
- `workstream add|close` edits `workstreams.yaml` in place, so its comments
  survive.

### The runtime split is enforced

- A PreToolUse hook denies the `strix-executor` subagent any edit under
  `.strix/` and any board move but `review` and `queue`, and asks before other
  Claude sessions edit project files. It is a guardrail, not a security
  boundary.
- Agents declare their tools: none can spawn agents, and `triage-agent` and
  `reviewer-agent` cannot write files.
- The main session is the orchestrator; agents return results instead of
  handing work to each other.
- The reviewer re-runs the checks the Execution Report lists (new `verify`
  capability) instead of trusting them, and reads the task's commits with
  `strix-task diff`.
- Executors commit with a `Strix-Task: <ID>` trailer and never commit `.strix/`.

### Routing

- Every intent × complexity cell has exactly one route, checked by
  `npm run validate`. TRIVIAL work takes a lite task and skips the reviewer;
  `arch` below STANDARD is reclassified.

### Generated, not repeated

- The executor rules for Cline, Copilot and Claude come from
  `templates/executors/_shared/`; `npm run gen` renders them, and the drift gate
  fails on a hand edit.
- The README's repository tree, the triage agent's intent list, and the routing
  and lifecycle tables are generated from config.
- `reference/workflow/router.md` is the one router document.

### Fixes

- `strix-task --help` works; a title containing `$`, `|`, a line break, or a
  control character can no longer corrupt a task file; `--priority` and
  `--complexity` are validated, and `EPIC` is refused.
- `strix-init` validates `--executor`, and neither `--force` nor the new
  `--force-executor` overwrites knowledge, the registry, the skill catalog, or a
  file you already had. Switching executors lists the old files instead of
  deleting them.
- The injected contract no longer contains a literal `${CLAUDE_PLUGIN_ROOT}`,
  and the hook parses quoted, commented, and CRLF config values.
- Slugs fold accents instead of dropping the letters.
- `package.json` declares `engines: node >= 22` and ships a `files` whitelist.

### Tooling

- CI runs the suite on Node 22, 24, and 26, on Linux and macOS (bash 3.2),
  plus shellcheck and a packaging check.
